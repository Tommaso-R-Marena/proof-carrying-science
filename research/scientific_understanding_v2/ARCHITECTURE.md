# Source, proposal, computation and authority

The existing `scientific_intake_v1.pipeline` captures exact bytes and exports its unchanged source/Claim-IR/obligation package under `intake/`. Its independent replay and authenticated cache are reused.

`interpretation.py` proposes bounded mathematical structures from source. It never executes project code. `dimensions.py` checks explicitly declared units. `model_checks.py` separately interprets a closed SBML subset and a static arithmetic subset of an upstream generated export. `rational_equivalence.py` independently normalizes rational functions under explicit denominator conditions. `document_checks.py` reconstructs supported examples through approved numerical kernels, not arbitrary doctest execution.

`checks.py` owns check dispatch. Consequential numerical/model work runs in `worker.py` with stripped credentials, fixed working directory, resource budgets, a process group and parent-owned scratch cleanup. These mechanisms do not create privilege separation or an OS sandbox.

`pipeline.py` attaches every candidate to exact source bytes, builds an experimental knowledge graph with blocking meaning-review nodes, executes authorized supported checks and emits an escaped HTML review. Results distinguish source observations, mathematical certificates, numerical comparisons, contradictions and unknowns. Cache keys bind source dependencies, context and policy. Independent replay recomputes source interpretations, graph, obligations, results and display and bypasses cached verdicts.

`corpus.py` only materializes pinned source bytes. `reference.py` supplies independently prepared internal evaluation probes after component freeze. `evaluation.py` grades without acting as a training/reward/verification oracle. Reference labels never enter runtime checking or model training. `retrieval.py` supplies untrusted source-relevance scores from a separately authored training corpus; no ranking score grants authority.

The formal profiles specify abstract dimensional typing, finite integer conservation and finite-sampling counterexamples. Python refinement, real ODE semantics, source intent and empirical validity remain separate open obligations. Existing production `pcs/`, root `formal/`, prior experiments and source-census contracts are unchanged.
