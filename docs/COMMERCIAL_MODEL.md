# Commercial Model

## Open foundation

Strong default candidates for genuine open source:

- assurance-kernel specification;
- portable certificate format;
- core verifier/checker;
- reference CLI;
- foundational formal semantics;
- basic academic adapters.

This is strategically useful because customers should be able to independently check evidence without trusting the vendor.

## Paid layers

Commercial value can live in:

- enterprise orchestration and policy;
- private/on-prem deployments;
- regulated/validated release management;
- domain packs with maintained rules and integrations;
- high-scale compute and artifact retention;
- identity/access controls and audit dashboards;
- integrations with scientific platforms, CI/CD, LIMS/ELN, cloud, and internal systems;
- SLA/support;
- custom assurance engineering;
- certification/independent red-team services;
- evidence preparation for internal quality/regulatory workflows.

## Initial services-to-software path

1. Perform computational assurance/red-team engagements manually using internal tooling.
2. Convert repeated checks into adapters.
3. Turn internal orchestration into customer-facing CI.
4. Standardize evidence package and dashboards.
5. Build enterprise/domain-pack recurring revenue.

This avoids requiring a complete platform before learning what customers will pay to verify.

## Ethical pricing principle

Charge primarily for commercial scale, integration, governance, support, and organizational value—not for access to basic scientific truth or the ability to inspect a certificate.
