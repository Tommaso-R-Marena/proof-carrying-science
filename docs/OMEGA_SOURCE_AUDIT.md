## Issues with genuine external prerequisites

At inventory time, core issues #75, #14, #13, #11 and #9 were open. Website #93 and #2 were open. CertiForge had none. A real external design partner, paid pilot, legal/key operations, historical third-party disclosures, a custom-domain decision, and reconciliation of the production D1 ledger cannot be made true by synthetic model training. Existing production schema objects predate most migration-ledger rows; blindly replaying old migrations can reset catalog rows. The local-first Omega workspace requires no database migration.

## Fifteen immediate deliverables, scoped to this cycle

1. Source-backed capability matrix and current repository inventory: this audit and retained API evidence.
2. Canonical Claim IR / Proof Obligation Graph: reuse existing formats through versioned explicit intake.
3. Deterministic search and counterexample API: pure Python functions and CLI, with independent receipt replay.
4. Reproducible dataset generation: seeded first-party family corpus, alpha/source/truth-pair leakage checks.
5. Small trainable repair ranker: actual weighted logistic action-ranking heads.
6. Real training/checkpoints: CPU weights, training digests and reward trace; no placeholder model API.
7. Held-out evaluation: fixed unseen families, strong baselines, bounded budgets, per-task failures and timings.
8. Learned search with independent checker: every proposed candidate replayed; no model-controlled acceptance.
9. Graph experiment: fixed typed AST message passing plus learned head and bag ablation; end-to-end GNN remains future work.
10. Minimal RL environment: constrained state/action/reward/termination interface, checker-controlled reward.
11. Baseline bandit: real one-step REINFORCE; long-horizon RL remains future work.
12. Proof-carrying optimization bridge: existing actual CertiForge checker integration; learned optimization and universal compiler refinement remain future work.
13. Scientific-intelligence CLI: intake, impact, check, search, replay, generation, training, evaluation, reproduction, kernel verification, environment, memory and optimization bridge.
14. Visual website workspace: explicit source/claims, inspectable graph, actual learned ranking and deterministic comparison, evidence downloads.
15. Real measurements/report: generated experiment artifacts and actual Lean theorem/axiom/rejection inventory; this cycle's release evidence records exact PR/CI/deployment identities.

## Subsequent dependency-driven research

First improve and independently test interpretation grounding and task realism. Add consented or licensed external tasks with frozen unseen evaluation before making transfer claims. Only then expand constrained retrieval and typed proof actions, train a message-passing encoder, evaluate larger models and true sequential RL, and consider optimization learning. Theory generation, proof-guided protocol/code synthesis, arbitrary-code isolation, multi-agent scientific coordination, institutional pilots and new formal meta-theorems remain separate uncompleted milestones. Concrete Boolean Lean targets do not establish these capabilities or proof of universal checker correctness.
