# Licensing disposition for the recorded model outputs

Prepared 2026-11-19 at the owner's request. **No permission to redistribute is assumed beyond what
the providers' terms show.** This is a reading of published terms, not legal advice; the owner may
want legal review before deciding L2. Nothing has been removed, rewritten or relicensed.

## 1. What is recorded: 45 outputs, not 35

The audit counted 35 because its provenance rule covered only `results/heldout/model_responses/`.
The 10 development responses under `results/dev/model_responses/` were classed as "generated by
PCS". That rule is corrected with this document, and the audit now counts 45.

| Group | Split | Provider route | Model identifier | Files | Generated |
| --- | --- | --- | --- | ---: | --- |
| G | held-out | Gemini API, free tier | `gemini-3.6-flash` | 18 | 2026-11-10 to 11 (held-out run) |
| G | development | Gemini API, free tier | `gemini-3.6-flash` / `gemini-3.5-flash-lite` | 3 / 2 | before the software freeze of 2026-11-10 |
| N | held-out | OpenRouter, free variant | `nvidia/nemotron-3-ultra-550b-a55b:free` | 17 | 2026-11-10 to 11 |
| N | development | OpenRouter, free variant | `nvidia/nemotron-3-ultra-550b-a55b:free` | 4 | before 2026-11-10 |
| C | development | OpenRouter, free variant | `cohere/north-mini-code:free` | 1 | before 2026-11-10 |

* **What each file holds.** Each file holds the provider and model identifier, a cache key, the
  model's text, token usage, the finish reason and the prompt's SHA-256. The 45 texts total 214,000
  characters. The single Cohere text is `{"claims": []}"`, an empty answer.
* **What a model saw.** The prompts held an open-licence article (CC BY 4.0) and a description of
  its data columns.
* **How they are used.** The model arms read these files as a cache (`allow_network=False`):
  * the development evaluation;
  * the prospective demonstration;
  * the capacity run;
  * analyses of the frozen run.

  No result uses the Cohere file.
* **Freeze status.** Neither freeze record (`FREEZE.json`, `BENCHMARK_FREEZE.json`) pins any of
  them.
* **Derived content.** The proposals parsed from these texts are also stored in receipts, bundles
  and results. Each proposal is a statistic, a column, rows, a printed number, and a quote from the
  article itself.

**Already public.** Both repositories are public. All 45 files have been readable on the public
draft branch of PR 212 since 2026-11-10/11 (commits `f17649ca`, `dbe31d72`, `87900a17`). They are not
in `main`. Admission (C1) would place them in `main`, so the disposition should be decided before C1.

The retrieval tool limits quotations to short excerpts; the full documents are at the URLs. Provider
routing at generation time is not recorded in the files. The providers below are those OpenRouter
lists today for each free variant, one endpoint each.

**Google: Gemini API Additional Terms of Service**, "Effective March 23, 2026", in force when the
outputs were generated (`https://ai.google.dev/gemini-api/terms`, which redirects to
`https://aistudio.google.com/docs/terms`).

* *Use of Generated Content*: "Google won't claim ownership over that content."; "You're responsible
  for your use of generated content, and for the use of that content by anyone you share it with."
  Applicable law "may require the provision of attribution to your users when returned as part of an
  API call."
* *Unpaid Services*: Google "uses the content you submit to the Services and any generated responses
  to provide, improve, and develop"; "human reviewers may read, annotate, and process your API input
  and output". The v1 run used the free tier (v1 `REPORT.md`), so these applied. The inputs were
  published open-licence articles.
* *Use Restrictions*: no developing models that compete with the Services, and the Prohibited Use
  Policy applies. Nothing restricts sharing generated content.

**OpenRouter: Terms of Service**, "Last Updated: August 31, 2026" (`https://openrouter.ai/terms`).

* §6.1: "Your ownership rights in the Output are set forth in the Model Terms for each Model you use."
* §5.1: you must comply with each model's terms.
* §5.8: those terms govern "to the extent required by the applicable Model Provider".
* §7(8): no distributing content that does not comply with the model's or provider's terms.

So rights in the N and C outputs depend on the model and provider terms.

## 3. Disposition

| Group | Files | Redistribution on the evidence | Recommendation |
| --- | ---: | --- | --- |
| G (Gemini) | 23 | **Supported.** Google claims no ownership and does not restrict sharing; the user is responsible for use and sharing | **L1: keep**, with a provenance note per file group: model, free tier, date, the terms' URL and effective date |
| N (Nemotron) | 21 | **Not established.** The user owns the outputs, and the model license puts no restriction on sharing outputs. But the provider's trial terms allow only "limited trial purposes", "internal testing and evaluation", "not in production". Publishing in a public repository is neither clearly permitted nor clearly prohibited | **L2:** (a) get NVIDIA's written confirmation, or legal advice, that publishing research outputs from trial access is permitted, then keep; or (b) before C1, replace each file's text with its digest and length, keeping the prompt digest and usage, and accept that the Nemotron arm can no longer be regenerated offline from the repository (kernel receipts, bundles and replays are unaffected); or (c) keep as is (not recommended without a) |
| C (Cohere) | 1 | **Not permitted.** Publication and distribution of Content are prohibited, and access for benchmarking is prohibited | **L3: remove before C1.** No result uses the file and no freeze pins it. Separately, the call itself may have conflicted with the benchmarking clause; no further Cohere use is planned |

* **Derived proposals** (in receipts, bundles and results) come from the same outputs. For G they are
  covered by L1. For N and C, removing them would invalidate frozen results, and they consist mainly
  of the article's own words and of field choices. They should follow the outcome of L2 (a); option
  (b) does not remove them.
* **History.** Deleting a file in a later commit does not remove it from Git history, or from copies
  already made of the public branch. A history rewrite would conflict with preserving historical
  evidence. It is not recommended unless a provider asks for it.
* **Effect on C1.** L2 (b) and L3 each change the admitted tree. They would be ordinary commits on
  the branch, before the evidence is regenerated and before C1.

## 4. Recommended disposition, for the owner's decision (2026-11-19)

The aim is to publish nothing further whose rights are unresolved, without losing provenance and
without touching history or frozen evidence. Nothing below has been done.

**L1, Gemini (23 files): keep.** Their provenance is recorded in
[`model_outputs_inventory.json`](model_outputs_inventory.json), one row per file:

* the SHA-256 and size;
* the model, finish reason, prompt digest and token usage;
* the SHA-256 and length of the text, but not the text;
* the applicable terms and status.

**L2, Nemotron (21 files), and L3, Cohere (1 file): withhold from further publication, with
provenance kept.**

1. The owner first archives the 22 original files privately, for example in a private repository
   or an encrypted archive, and checks each against `original_sha256` in the inventory.
2. On the owner's recorded decision, the 22 files are replaced in the branch by provenance stubs.
   This is one ordinary commit, made with
   `python -m research.claimcheck_v1_1.governance.withhold_model_outputs --apply --groups N,C --decision "<reference>"`.
   * Each stub keeps the path, the provider and model, the cache key, the prompt digest, the usage,
     the finish reason, the digest and size of the original and of its text, the terms, and the
     reason.
   * Nothing outside `results/*/model_responses/` changes.
3. In parallel, ask NVIDIA whether publishing research outputs obtained through trial access is
   permitted (L2(a)). If it is, the 21 originals can be restored from the archive in a later
   commit; the digests prove they are the same bytes.
4. The Cohere response is an empty answer (`{"claims": []}"`) and no result uses it. Withholding it
   rather than deleting it keeps its record.

What withholding changes, and what it does not:

| | Effect |
| --- | --- |
| frozen evidence | **none.** Neither freeze record pins these files; the frozen results, receipts, bundles and replays are unchanged and still verify |
| tests | **none.** No test reads the raw responses (checked) |
| reproducibility | regenerating the Nemotron arm offline needs the private archive. Affected: the development evaluation (`dev_arms.json`), the prospective demonstration, bundle export and the development half of the capacity run. Their committed results stay as they are |
| derived proposals | the parsed readings inside receipts, bundles and results stay. Removing them would invalidate frozen results. They consist mostly of the article's own words and of field choices, and their status follows L2(a) |
| admission | the stubs are what C1 admits. Decide L1 to L3 first, then regenerate the evidence |

**What public Git history means.**

* The 22 originals have been readable since 2026-11-10/11 in the public branch, in commits
  `f17649ca`, `dbe31d72` and `87900a17`. GitHub keeps every commit of an open or closed pull
  request reachable through the pull request itself (`refs/pull/212/head`). Clones and forks made
  since are outside anyone's control.
* Replacing the files stops further publication in the admitted tree, in any release, and in
  `main`. The last point holds only if PR 212 is **squash-merged**, which is the repositories'
  linear-history practice. A merge commit or a rebase-merge would carry the earlier commits, and so
  the originals, into `main`'s history for good.
* Withdrawing what has already been exposed would need three things:
  * a rewrite of the branch's history, which needs your authorisation and conflicts with
    preserving historical evidence;
  * a request to GitHub Support to purge cached views and pull-request references;
  * acceptance that existing clones are unaffected.

  This is **not recommended** unless a provider asks for it.

**Recommendation in one line:** L1 keep; L2 withhold now and ask NVIDIA (restore if permitted); L3
withhold; squash-merge only; no history rewrite.
