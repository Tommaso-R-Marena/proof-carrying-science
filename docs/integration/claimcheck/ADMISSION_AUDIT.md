## Making the review tractable without deleting evidence

Of the 1,995 files, about 70 are code and Lean (about 0.65 MB): these need reading line by
line. The rest are records whose correctness is mechanically checkable, and should be reviewed that
way rather than by reading:

1. **frozen inputs and results:** their digests are pinned by `FREEZE.json` and
   `BENCHMARK_FREEZE.json`, which were committed before any held-out result; `freeze check` verifies
   all of them;
2. **evidence bundles:** `replay_independent.py` re-derives every proof file from its receipt and
   re-runs the Lean kernel; `crosscheck_bundles.py` checks that every bundle gives every proposal the
   result of the frozen run; the hosted job `offline-and-kernel` replays one bundle on each run;
3. **duplicates:** the census lists every file with its digest, so a reviewer reads each distinct file
   once.

If the owner prefers smaller review units, the same retained-source mechanism can admit the addition
in two steps (code, Lean and documents first; frozen records and bundles second), each with its own
successor manifest. That doubles the owner-held steps and removes nothing. Moving the records out of
the repository (for example to a release asset pinned by digest) would shrink the tree, but makes the
evidence harder to replay and is not recommended.
