# Proposed source admission of the ClaimCheck research sidecar

**Status: a proposal, prepared and dry-run tested. Nothing protected has been changed and nothing
is approved.** `source-policy` and `verified-public-integration` are red on the draft PR and stay
red until the owner decides.

## What the protected gates require

1. `research/integration_v2/reconcile.py` (run by `source-policy`) compares the complete set of
   tracked files, and every file's bytes and mode, with the reviewed manifest
   `RECONCILIATION_V22.json`, whose SHA-256 is compiled into the gate. A branch that adds a file
   fails with `combined tracked file census differs`. This is the intended behaviour.
2. `scripts/check_reconciled_prs.py` requires every non-control file to equal a retained source
   commit that is identified by commit id **and** by an annotated tag.

So admitting new files takes three things, none of which an assistant can approve: a successor
manifest, new constants compiled into the two control programs, and a new retained commit with a tag
pushed to the repository.

## Dry run

[`dry-run.json`](dry-run.json), produced by
`python -m research.claimcheck_v1_1.governance.prepare_core_admission`. In a throw-away worktree the
script generated the successor, applied the constants there, and ran the unmodified logic of both
gates:

* the gate on `main` today passes (V22, 72 PRs, 8,042 files), checked on a worktree of `origin/main`;
* with the successor: `reconcile --require-committed` passes (72 PRs, 10,004 files) and
  `check_reconciled_prs.py --core` passes against a local, unpushed tag;
* rejected, as they must be: an unlisted extra file; an edited admitted file; an edited existing
  production file; an edited successor manifest; a tag pointing at another commit.

The local tag and worktree were deleted. Nothing was pushed.

## What the owner would do, if the answer is yes

1. Review the census and this proposal.
2. Fix the commit to admit (the PR head at that time) and run the script again at that commit: the

3. Create the retained commit as the script describes (same tree as the source commit; parents: the
   source commit and the previous retained commit) and push an annotated tag
   `pcs-source-intake/core-claimcheck-v1-<date>` to it. This is the step that cannot be done from
   this session and should not be.
4. Have the control changes committed (the patch, the generated manifest, the test and note
